> **testID reality (recounted against source 2026-07-31, third pass):** the feature exposes **36 literal testIDs plus 7 dynamic families** — up from "32 literal + 7 dynamic" at the 2026-07-20 second pass. The four new ids landed via two shipped-but-undocumented controls this pass found and backfilled with rows (LANG-LEARN-043–047, LANG-MORE-027/028): **Learn** gained the ambient notification-permission card, `language-learn-notification-permission-card` plus its `layout="compact"` children `-action` and `-dismiss` (`LanguageLearnScreen.tsx:205`, shipped 2026-07-27/30); **More** gained the `MORE SYMPLY APPS` section row `language-more-symply-apps` (`LanguageMoreScreen.tsx:154`, shipped 2026-07-21 in the same commit as the AI-entry unification but missed by the pass that documented that commit). Per screen: **More** — root, `language-more-scroll`, `-profile`, `-notifications`, `-sign-out`, `-ai-assistance`, `-symply-apps`, `-data-section`, `-reset-learning` (the local `SettingItem` takes a `testID` passthrough prop, so any future row is addressable the same way); **Learn** — root, `language-learn-scroll`, `language-learn-notification-permission-card` (+ `-action` / `-dismiss`), `language-learn-daily-goals`, plus the families `language-learn-nav-${card.key}` (`-assessment` / `-plan` / `-review` / `-dialogue` / `-tutor`) and `language-learn-goal-${goal.id}` (`-review` / `-speak` / `-learn`); **Tutor** — root, `language-tutor-messages`, `language-tutor-composer`, `language-tutor-user-message`; **Dialogue** — root, `language-dialogue-generated`, plus the family `language-dialogue-scenario-${s.id}` (5 values); **Assessment** — root, `language-assessment-question-meta`, `language-assessment-submit`, `language-assessment-input`, `language-assessment-retry`, `language-assessment-continue`, plus the family `language-assessment-option-${i}` (index-keyed, one per MCQ option, also carrying `accessibilityRole="radio"` + `accessibilityState={{ selected }}`); **Plan** — root, `language-plan-start-assessment`; **Review** — root, `language-review-flashcard`, the **state-suffixed pair** `language-review-done-complete` / `language-review-done-empty` (one ternary, two ids — see LANG-REVIEW-028), plus the family `language-review-rating-${r.rating}` (`-1` / `-2` / `-3` / `-4`); **Onboarding** — root `language-onboarding-screen`, `language-onboarding-start`, plus the families `language-onboarding-native-${lang.toLowerCase()}` (10 chips, `accessibilityRole="radio"`) and `language-onboarding-motivation-${m.id}` (5 chips, `accessibilityRole="checkbox"`). Line numbers throughout this file drift by a few lines from small unrelated edits (e.g. Assessment's screen picked up a shared `keyboardDismissScrollProps` import); treat cited line numbers as approximate pointers, not exact addresses.
>
> The Maestro flows migrated to the **first** wave of these IDs, so nav cards, daily goals, More rows, scenario tiles, the Tutor composer, and the Assessment submit are selected deterministically rather than by copy. The **second** wave — everything listed above for Assessment options / input / **Try again** / **Continue to my plan**, Review flashcard / ratings / **Done**, the Plan CTA, and all of Onboarding — is **shipped in source but not yet adopted by any flow**, so those surfaces are still copy-matched *in the flows* until `e2e/maestro/language/` is updated; no flow run has been possible since the rollout (insufficient disk for an iOS build). Dynamic copy behind those controls (streak count, `Question N of M`, due badge) is still matched by regex or not at all. The **third** wave — the notification-permission card and the Symply-apps row — has **no** flow reference at all yet (not even a copy-matched one); see `FLAG-LANG-027`. The **Plan header back chevron** was briefly recorded as an unshipped control; it is not. It is rendered by the shared `src/components/common/ScreenHeader.tsx`, which forwards `backButtonTestID` to `BackButton` — and `BackButton` *defaults* that id to `nav-back-button` (`src/components/common/BackButton.tsx:59`). The chevron is therefore already deterministically addressable, and the Language flows already tap it by that id (e.g. `learn-home.yaml`). Passing a bespoke per-screen id would be churn with no automation benefit, since only one back button can exist on a screen. See `FLAG-LANG-026` for the remaining work order (flow adoption only).
>
> **Onboarding is no longer one screen.** `LanguageOnboardingScreen`'s **[ Start learning ]** now hands off to the shared `EssentialPermissionsScreen` (`src/screens/onboarding/EssentialPermissionsScreen.tsx`, registered as `EssentialPermissions` in the same `OnboardingNavigator` stack) instead of completing onboarding itself — shipped 2026-07-27 (`73e7fc2b`). `completeOnboarding()` and `router.replace('/')` now live on that screen, not in `LanguageOnboardingScreen.finish()`. See LANG-ONBD-023–026 and `FLAG-LANG-028`.
